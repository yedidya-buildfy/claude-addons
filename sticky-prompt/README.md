# sticky-prompt — ההודעה ששלחת ננעצת בראש הטרמינל

בזמן שסשן של Claude Code רץ, השורה הנעוצה בראש הטרמינל של VS Code מראה תמיד את אותו דבר — את פקודת ה‑shell שפתחה את הסשן (`claude --dangerously-skip-permissions`). היא אף פעם לא משתנה, כלומר היא לא אומרת כלום. כדי להיזכר מה ביקשת, צריך לגלול למעלה ולחפש את התיבה עם המסגרת הלבנה.

עם התוסף הזה, הבלוק הנעוץ בראש הוא **תיבת ההודעה שלך עצמה** — אותה תיבה, אותו טקסט. גוללים מעל ההודעה האחרונה, והנעוץ הופך לזו שמעליה. לחיצה עליו קופצת חזרה להודעה.

## איך זה עובד

השורה הנעוצה היא תכונה מובנית של הטרמינל ב‑VS Code ("sticky scroll"). היא לא יודעת דבר על Claude — היא נועצת את מה שהטרמינל חושב שהיא הפקודה שרצה בראש התצוגה, ולומד על פקודות מרצפי סימון בלתי‑נראים שה‑shell שולח לו. אין שום דבר שמונע מתוכנית אחרת לשלוח את אותם סימונים — השאלה היחידה היא איפה הם נוחתים.

שתי דרכים פשוטות יותר נוסו ונפלו, ושתיהן הסיבה שהתוסף בנוי כמו שהוא בנוי:

- **כתיבה ישירה למכשיר הטרמינל מתוך hook** — לא שורדת. Claude מצייר מחדש את אזור התחתית בכל פריים ומוחק כל מה שתהליך חיצוני כתב שם. הסימון כן נשאר, ונתקע על שורה אחרת לגמרי שהתמלאה אחר כך בתוכן של Claude.
- **הדפסה דרך Claude עצמו** (הודעת מערכת של hook) — כן שורדת, אבל Claude מסנן רצפי בקרה, אז הסימונים לא מגיעים לטרמינל בכלל.

לכן התוסף יושב באמצע: `sticky-claude` מריץ את Claude Code מאחורי פסאודו‑טרמינל, ומזריק את הסימונים **לתוך הפלט של Claude עצמו** — בדיוק בבייטים שבהם הוא מצייר את תיבת ההודעה. ככה הם נוחתים על השורות האמיתיות, ואף אחד לא מצייר עליהן מחדש.

מה שמזוהה: Claude מצייר הודעה שנשלחה כבלוק עם צבע רקע, שהשורה הראשונה שלו נפתחת בסימן `❯`. הצירוף הזה לא מופיע בשום מקום אחר — גם לא בתיבת הקלט בזמן שמקלידים. סימון "תחילת פקודה" נכנס לפני השורה הראשונה של הבלוק, ו"הפקודה רצה" בסוף השורה האחרונה שלו, כך שנעוצות בדיוק שורות ההודעה.

## כמה שורות נעוצות

**שלוש: הראשונה, השנייה והשלישית** של ההודעה, תמיד.

זה לא מושג ע"י בקשה מ‑VS Code אלא ע"י כך שהסימון הסוגר מוצב בסוף השורה השלישית של הבלוק ולא בסוף האחרונה. ככה גובה ה"פקודה" הוא בדיוק שלוש שורות, ו‑VS Code לא צריך להחליט לבד איזה חלון להראות מתוך הודעה ארוכה — החלטה שתלויה גם באיפה בדיוק גוללת, ושהיא זו שגרמה לשורה הראשונה ליפול.

לשינוי: משתנה סביבה `STICKY_PROMPT_ROWS`. שים לב שגם `terminal.integrated.stickyScroll.maxLineCount` צריך להיות לפחות באותו גובה (ההתקנה מגדירה 3, המקסימום שהוא מרשה הוא 10), וש‑VS Code בכל מקרה לא נועץ יותר מ‑40% מגובה הטרמינל.

## איך מפעילים

ההתקנה מוסיפה alias ל‑`~/.zshrc` שמפנה את הפקודה `claude` לעוטף. צריך טרמינל חדש (או `source ~/.zshrc`) כדי שייטען.

```bash
claude                 # דרך העוטף
command claude         # ישירות, בלי העוטף
```

העוטף מעביר הכול כמו שהוא — קלט, פלט, שינוי גודל חלון, וקוד היציאה. אם הפלט לא טרמינל (למשל בצינור), הוא מסתלק מהדרך ומריץ את Claude ישירות.

## דרישות

- VS Code (דיאלקט הסימונים כאן הוא של VS Code בלבד)
- שילוב shell של VS Code פעיל — ברירת המחדל; זה מה שגורם לשורה הנעוצה להופיע מלכתחילה
- `terminal.integrated.stickyScroll.enabled` דלוק (ברירת מחדל)
- Python 3 (מגיע עם macOS)

## בדיקה

```bash
./selftest.sh
```

מריץ הקלטות אמיתיות של תיבות הודעה דרך ההזרקה ובודק: שהפקודה הקודמת נסגרת, שהסימון הפותח יושב לפני הבלוק ולא בתוכו, שהסימון הסוגר יושב בסוף השורה השלישית (או האחרונה, בהודעה קצרה) ולפני כיבוי צבע הרקע, שהשורות מעבר לשלישית נשארות כמו שהן, שכל ההודעה הופכת לשם הפקודה, ששום בייט אחר לא השתנה, שבלוק שנחתך בין שתי קריאות עדיין מסומן, ושבריחה של נקודה‑פסיק ולוכסן עובדת.

לבדיקה ידנית על הקלטה משלך:

```bash
./sticky-claude --filter < recorded.bin | cat -v
```

## אם העיגולים בשוליים מפריעים

VS Code מוסיף עיגול קטן בשוליים השמאליים ליד כל "פקודה". עכשיו יש אחד כזה ליד כל הודעה. לכיבוי, בהגדרות של VS Code:

```json
"terminal.integrated.shellIntegration.decorationsEnabled": "never"
```
