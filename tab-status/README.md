# tab-status — נקודה צבעונית על ה‑tab של הטרמינל ב‑VS Code

כל סשן של Claude Code מקבל קידומת של עיגול צבעוני על כותרת ה‑tab בטרמינל של VS Code, שמשקפת במבט אחד את המצב הנוכחי של Claude:

| נקודה | משמעות |
|---|---|
| ⚪ | הסשן רק התחיל, עוד לא הורצו פקודות |
| 🔴 | Claude מעבד את הפרומפט שלך |
| 🟣 | Claude עובד **במצב תכנון** (plan mode) — בונה תוכנית, עוד לא נוגע בקוד |
| 🟠 | התוכנית מוכנה ומחכה ל**החלטה שלך** (אישור / דחייה) |
| 🔵 | Claude מחכה לתשובה שלך לשאלה (`AskUserQuestion`) |
| 🟡 | התשובה הראשית הסתיימה, **סוכנים** (subagents) עדיין רצים ברקע |
| 🟤 | התשובה הראשית הסתיימה, **shells של Bash** עדיין רצים ברקע |
| 🟢 | פנוי / סיים, מוכן לפרומפט הבא |

הכל עיגולים בכוונה — יוניקוד מציע בדיוק תשעה עיגולי צבע, וזה כל מה שהמערכת משתמשת בו, כדי שסריקה מהירה של שורת ה‑tabs תהיה קריאה אחת של צבע ולא של צורות.

🟡 לעומת 🟤 מאפשר להבדיל בין שני סוגי עבודת הרקע: 🟡 = `Agent`/subagent עדיין רץ, 🟤 = פקודת `Bash` שהרצת עם `run_in_background:true` עדיין חיה. אם שניהם רצים, 🟡 מנצח.

בניגוד לשאר המצבים, 🟤 **לא** מונע ע"י hook — Claude Code לא משדר אירוע "background shell finished", אז לא היה מה שינקה את הנקודה. במקום זה ה‑watcher סופר ישירות את ה‑shells החיים ברקע (תהליכי zsh שהם ילדים של תהליך ה‑`claude` ב‑TTY הזה ומריצים shell-snapshot eval, בדגימה של ~3 Hz בזמן idle). כשה‑shell מסתיים, התהליך שלו נעלם והנקודה חוזרת לבד ל‑🟢.

## שתי הנקודות של מצב תכנון

לפני שהן נוספו, כל מצב תכנון נראה בדיוק כמו עבודה רגילה — אדום — כולל הרגע החשוב ביותר, שבו התוכנית כבר מוכנה ו‑Claude פשוט עומד ומחכה שתאשר. כלומר, ה‑tab שדרש פעולה מיידית ממך נראה כמו tab שאפשר להתעלם ממנו.

- **🟣 בונה תוכנית** — נקרא ישירות מיומן השיחה של הסשן (רשומת `permission-mode` האחרונה), ולא מ‑hook. זו הסיבה שגם מעבר ידני למצב תכנון עם shift+tab נתפס, למרות שהוא לא משדר שום אירוע. במצב "פנוי" הנקודה נשארת ירוקה — "סיימתי, תורך" חשוב יותר מ"אני במצב תכנון".
- **🟠 מחכה להחלטה** — נדלק כשה‑hook של `ExitPlanMode` נורה לפני שהכלי נחסם על בחירת המשתמש, ונכבה ב‑hook שאחריו. אם דוחים את התוכנית עם Escape לא נורה hook סיום, אז הפרומפט הבא שלך מנקה את הנקודה בעצמו.

🟠 גובר על 🟣 — מבין השניים, זה שדורש פעולה ממך מנצח.

## איך זה עובד

שני סקריפטים פלוס שבעה hooks של Claude Code:

- **`tab.sh`** — מטפל ה‑hook. מקבל את האירוע (`white`, `red`, `blue`, `green`, `bg-inc`, `bg-dec`, `session-end`) ומעדכן קובץ מצב פר‑סשן ב‑`~/.claude/terminal-state/<session>.state`. **לא** מצייר ישירות.
- **`tab-watcher.sh`** — מורץ ע"י `tab.sh` ב‑SessionStart (ומורץ מחדש מעצמו בכל hook מאוחר יותר אם הוא חסר). רץ ברקע לאורך כל חיי הסשן של Claude, קורא את קובץ המצב וכותב רצפי escape של OSC (`\033]0;<dot> <name>\a`) ל‑TTY הנוכחי כל 300 ms.
- **`tn`** — CLI קטן שמגדיר/מנקה עקיפת שם פר‑טרמינל. ניתן לקריאה מה‑shell שלך (דרך פונקציית ה‑zsh בשם `tn()`) **או מכלי ה‑Bash של Claude**.

### למה ה‑tab לא מהבהב

ה‑watcher בודק את המצב 50 פעמים בשנייה, אבל **כותב** את הכותרת רק כשהיא באמת השתנתה, ומעבר לזה פעם ב‑200 מ"ש כדי לקחת בחזרה את הכותרת מ‑Claude Code. כתיבה של אותה כותרת עצמה 50 פעמים בשנייה גרמה ל‑tab להבהב.

אם עדיין רואים הבהוב, הוא כנראה מגיע ממחוון ההתקדמות של Claude Code עצמו (רצף OSC 9;4 שנשלח בפעולות ארוכות). אפשר לכבות אותו בהגדרות: `terminalProgressBarEnabled: false`.

ה‑watcher קיים כי Claude Code עצמו משדר רצפי כותרת של OSC (התווית האוטומטית של הסשן, למשל `* Count to ten in Hebrew`). ציור חד‑פעמי מתוך ה‑hook היה מפסיד במירוץ — Claude כותב מחדש את הכותרת אחרי שה‑hook שלנו חוזר. ה‑watcher מצייר מהר מספיק (5 Hz) כדי שננצח תוך ~300 ms מכל כתיבה של Claude, אז הנקודה נשארת יציבה.

## ה‑hooks המחוברים

| Hook | פעולה | מצב |
|---|---|---|
| `SessionStart` | `tab.sh white` | ⚪ |
| `UserPromptSubmit` | `tab.sh red` | 🔴 |
| `PreToolUse` (matcher: `Agent`) | `tab.sh bg-inc` | מונה בלבד |
| `PreToolUse` (matcher: `AskUserQuestion`) | `tab.sh blue` | 🔵 |
| `PostToolUse` (matcher: `AskUserQuestion`) | `tab.sh red` | 🔴 (חזרה לעבודה) |
| `PreToolUse` (matcher: `ExitPlanMode`) | `tab.sh plan-wait` | 🟠 |
| `PostToolUse` (matcher: `ExitPlanMode`) | `tab.sh plan-done` | מנקה את 🟠 |
| `SubagentStop` | `tab.sh bg-dec` | מונה בלבד |
| `Stop` | `tab.sh green` | 🟢, או 🟡 אם `bg > 0`, או 🟤 אם shells של רקע חיים |
| `SessionEnd` | `tab.sh session-end` | ניקוי |

## קבצי מצב

ב‑`~/.claude/terminal-state/`:

| קובץ | תוכן |
|---|---|
| `<session>.state` | `white` / `red` / `blue` / `green` |
| `<session>.bg` | מונה סוכני רקע (מספר שלם) |
| `<session>.bg_hint` | חותמת זמן של שיגור סוכן רקע טרי, עד שיומן השיחה מדביק אותה |
| `<session>.plan_wait` | קיים כל עוד תוכנית מחכה להחלטה שלך (🟠) |
| `<session>.pinned` | קיים אם *אתה* קבעת את השם ידנית — Claude לא ידרוס אותו |
| `<session>.name` | שם התצוגה של ה‑tab (אוטומטי = שם תיקיית הפרויקט) |
| `<session>.watcher_pid` | ה‑PID של ה‑watcher הרץ |
| `tty.<ttysNNN>.session` | מיפוי הפוך מהטרמינל לסשן החי, כדי ש‑`tn` יפגע בסשן הנכון גם כש‑VS Code ממחזר מספרי TTY |
| `tty.<ttysNNN>.name` | עקיפה ידנית לטרמינלים שאין בהם סשן של Claude |
| `hooks.log` | כל הרצה של hook |
| `watcher.log` | התחלה/יציאה של ה‑watcher + heartbeat כל ~6 שניות |

## שינוי שם ידני ל‑tab

```bash
tn payplus            # נועץ את השם. Claude לא ישנה אותו יותר לבד
tn --auto payplus     # קובע שם בלי לנעוץ (זה מה ש‑Claude עצמו מריץ)
tn                    # משחרר את הנעיצה, חזרה לשם האוטומטי (שם תיקיית הפרויקט)
```

הנעיצה חוסמת רק שינוי־שם אוטומטי. הנקודה הצבעונית ממשיכה להתעדכן כרגיל.

### חשוב: אל תשנה שם דרך לחיצה ימנית ב‑VS Code

הצבע מגיע מכותרת שנכתבת שוב ושוב אל הטרמינל עצמו, וההגדרה `terminal.integrated.tabs.title` מוגדרת ל‑`${sequence}` — כלומר "הצג את מה שהטרמינל אומר". לחיצה ימנית → **Rename** מחליפה את זה בתווית *קבועה* לאותו tab, ומאותו רגע VS Code מתעלם מכל מה שנכתב מהטרמינל. השם נשאר, הנקודה קופאת. זה לא באג בסקריפט — זו התנהגות של VS Code, ואין דרך לבטל אותה מבחוץ.

- **במקום זה:** `tn <שם>` — נותן בדיוק את אותו שם קבוע, וגם נועץ אותו כך ש‑Claude לא ידרוס אותו, והנקודה ממשיכה להתעדכן.
- **לשחזור tab שכבר שינית ידנית:** לחיצה ימנית → Rename → למחוק את כל הטקסט → Enter. זה מחזיר את ה‑tab להצגת הכותרת מהטרמינל, והנקודה חוזרת מיד.

## איך נקבע השם האוטומטי

השם נקבע ע"י קוד, לא ע"י ה‑assistant שאיתו אתה מדבר. `tab-autoname.py` רץ כ‑hook על כל פרומפט:

1. **ברירת מחדל** — כשה‑watcher עולה, השם נקבע לשם תיקיית הפרויקט. זו רק כתובת זמנית.
2. **שאלה אחת למודל זול, על כל פרומפט** — ה‑hook שולח את **השם הנוכחי של ה‑tab** ואת ההודעה החדשה שלך, ושואל: האם השם עדיין מתאים? המודל מחליט גם *אם* להחליף וגם *למה*. ברירת המחדל היא gateway מקומי (`http://localhost:20128`) עם מודל חינמי.
3. **החלה** — התשובה עוברת סינון (מרכאות, סימני פיסוק, יותר מדי מילים = נדחית) ונכתבת לשם ה‑tab.

התשובה הרגילה היא "השאר" — המשכים, אישורים, תיקונים והודעות קצרות לא מזיזים את השם. רק מעבר אמיתי לעבודה אחרת מייצר שם חדש. אם עוד אין שם וההודעה היא "היי", המודל מחזיר "אין נושא" והשאלה חוזרת בפרומפט הבא.

השם נכתב **בשפה שבה כתבת**: פרומפט בעברית מקבל שם בעברית, ומעבר לנושא אחר בעברית מקבל שם עברי חדש. **שתי מילים כמטרה, שלוש לכל היותר.**

ה‑hook חוזר מיד ומריץ את הקריאה בתהליך מנותק — פרומפט שלך לא מחכה לרשת אף פעם, גם כשהניתוב האיטי לוקח 20 שניות.

אם הקריאה **נכשלת** (ה‑gateway כבוי, אין רשת), נרשם סימון כישלון — ורק אז מוזרקת ל‑Claude בקשה לבחור שם בעצמו. זה מסלול הגיבוי היחיד שבו ה‑assistant מעורב בכלל.

| משתנה סביבה | ברירת מחדל |
|---|---|
| `TAB_NAME_API` | `http://localhost:20128/v1/chat/completions` |
| `TAB_NAME_MODEL` | `auto/best-free` |
| `TAB_NAME_TIMEOUT` | `40` שניות |

בדיקה עצמית של הסינון: `python3 ~/.claude/scripts/tab-autoname.py --selftest`

### שלוש הסיבות שהשם לא נתפס

- **ההחלטה הייתה תלויה ב‑assistant.** קודם ה‑tab קיבל שם רק אם Claude נזכר לעשות את זה, וההוראה נשלחה רק פעם אחת בתחילת הסשן — מוקדם מדי, לפני שנאמר על מה מדובר. אם הוא לא בחר שם בשני התורות הראשונים, ה‑tab נשאר עם שם התיקייה עד הסוף. היום קוד עושה את זה, בכל פרומפט, עד שיש שם.
- **השם ננעץ מוקדם מדי.** `tn <שם>` נועץ, `tn --auto <שם>` לא. הוראה ישנה גרמה לנעיצה כבר של הניחוש הראשון, ומאותו רגע אי אפשר היה לתקן. היום הנעיצה שמורה לשם ש**אתה** הכתבת.
- **השינוי נפל לקובץ שאף אחד לא קורא.** `tn` מזהה לאיזה סשן שייך הטרמינל דרך מיפוי הפוך שה‑watcher כותב. בעבר המיפוי נמחק כשה‑watcher נסגר, אז בין סגירה להפעלה מחדש שינוי שם פשוט נעלם בשקט. היום המיפוי שורד את ה‑watcher, ואם בכל זאת אין סשן חי — `tn` אומר את זה בקול במקום להיראות כאילו הצליח.

## משתלב היטב עם התוסף `skill-tab-name`

אם תתקין גם את [`skill-tab-name`](../skill-tab-name), Claude יבחר אוטומטית שם מתאים לנושא עבור כל סשן ויחיל אותו דרך ה‑CLI בשם `tn` שמגיע כאן. השניים עצמאיים — `tab-status` עובד מצוין גם בלי הסקיל (פשוט קובעים שמות ידנית עם `tn <name>`).

## ניפוי באגים

```bash
tail -f ~/.claude/terminal-state/watcher.log   # heartbeat every ~6 s, includes paint_ok=1/0
tail -f ~/.claude/terminal-state/hooks.log     # every hook fire
ps -ef | grep tab-watcher | grep -v grep       # running watchers
~/.claude/scripts/tab-dots-selftest.sh         # קריאת יומן השיחה: בדיקה עצמית
```

אחרי עריכה של `tab-watcher.sh` צריך לסגור את ה‑watchers הרצים (`pkill -f tab-watcher.sh`) — כל אחד מהם מריץ עותק של הקוד הישן בזיכרון. הם נדלקים מחדש לבד ב‑hook הבא של כל סשן.

אם `paint_ok=0` באופן עקבי, ה‑watcher לא מצליח לכתוב ל‑`/dev/<tty>` — בדוק שמכשיר ה‑TTY קיים וניתן לכתיבה.

אם אין watcher רץ לסשן שאמור להיות לו אחד, פשוט שלח פרומפט באותו טרמינל — הסקריפט יתקן את עצמו ע"י הרצת watcher חדש.
