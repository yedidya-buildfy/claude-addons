# multi-model

הרצת **Claude Code כמעטפת** — עם ההרגלים, הסקילים, ההוקים וההרשאות שלך — אבל
על המודלים של המנויים האחרים שלך: ChatGPT/Codex, Grok, ו‑Antigravity של גוגל
(וגם Claude ו‑Kimi, אם תרצה).

ההתחברות היא **דרך המנויים בלבד (OAuth בדפדפן)**. אין שום מפתח API בתמונה, ואין
שום נפילה חזרה לחיוב לפי שימוש.

המודלים של הספקים האחרים רצים **בתוך Claude Code** — אותו Bash, אותו עריכת
קבצים, אותם סוכני משנה. הם לא מפעילים את המעטפת הנפרדת של Codex או של Grok.

## איך זה בנוי

בין Claude Code לספקים יושב [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI),
שרת קטן שרץ אצלך על המחשב ומאזין **רק ל‑127.0.0.1**. הוא מחזיק את חיבורי ה‑OAuth
שלך ומתרגם בין הפרוטוקולים, כך שכל מודל נראה ל‑Claude Code כמו מודל רגיל.

הפקודה `ccx` מרימה את השרת אם הוא כבוי ומפעילה את Claude Code מולו. **את רשימת
המודלים Claude Code מושך בעצמו מהשרת** — כל מודל שהשרת מגיע אליו מופיע בתפריט
`/model` עם השם הקריא שלו. אין רשימת מודלים קשיחה בשום מקום; מודל שייצא מחר
יופיע מעצמו ברגע שהשרת יידע עליו.

התפריט מציג **רק את הדור הנוכחי של כל קו מודלים** — אופוס אחד, סונט אחד,
Gemini Pro אחד, גרוק אחד. גרסאות שעבר זמנן נעלמות מעצמן ברגע שיוצאת חדשה
יותר, וכך גם דגמים מוקטנים (mini/lite), דגמי צד ומחוללי תמונות ווידאו.
הסדר: **קלוד ← ChatGPT ← Antigravity ← גרוק**.

הסינון עצמו נעשה בצד השרת ומחושב מהשמות הקריאים של המודלים ומספרי הגרסה שלהם,
לא מרשימת שמות קבועה. `ccx --refresh` בונה אותו מחדש; `ccx --list --all` מראה
גם את המוסתרים.

## ברירת המחדל וה‑effort

בדיוק כמו ב‑Claude Code רגיל: המודל וה‑effort שבחרת אחרון הופכים לברירת המחדל
לסשנים הבאים. ל‑ccx יש **זוג משלו** — הבחירה שלך בסשן ccx נשמרת לסשן ccx הבא,
ובסיום הסשן ברירת המחדל של `claude` הרגיל מוחזרת למקומה. בלי זה, מודל של ספק
אחר היה נשאר בהגדרות המשותפות ו‑`claude` הרגיל היה נשבר.

אם סשן נהרג בכוח (kill -9) הוא לא מספיק להחזיר — הסשן הבא מזהה את זה לפי מזהה
התהליך שנשמר, ומחזיר. `ccx --status` מתריע כשזה המצב.

כשהמתג כבוי, `claude` מתנהג בדיוק כמו קודם — ההתחברות, המודלים וברירת המחדל
המקוריים שלו, בלי שום מגע בשרת המקומי.

## סוכני משנה של ספקים אחרים

`ccx --agents` יוצר סוכן משנה אחד לכל ספק שאינו קלוד, מוצמד למודל הנוכחי שלו:

```
ask-chatgpt       → GPT 5.6
ask-antigravity   → Gemini 3.1 Pro
ask-grok          → Grok 4.6
```

בתוך סשן רב‑מודלי אפשר להעביר להם עבודה כמו לכל סוכן אחר, והם רצים עם אותם
כלים — קריאת קבצים, עריכה, הרצת פקודות. הלולאה הראשית יכולה להישאר על קלוד
בזמן שהסוכן רץ על ספק אחר. נבדק: ג'י‑פי‑טי וגרוק הריצו פקודות shell אמיתיות
והחזירו את הפלט.

הקבצים נוצרים מחדש בכל `ccx --refresh`, כך שכשייצא דור חדש הם יצביעו אליו לבד.
עריכות ידניות בהם נדרסות.

## גודל הקונטקסט

Claude Code מכיר את גודל הקונטקסט רק של המודלים של Anthropic, ולכל השאר הוא
מניח 200k — כלומר היה מכווץ את הסשן הרבה לפני שהוא באמת מתמלא. `ccx` לוקח את
הגודל **מהספק עצמו**, כפי שהוא מדווח עליו:

| מודל | אמיתי | מה שהיה מונח | מה שהיה מתבזבז |
|---|---|---|---|
| Gemini 3.6 Flash / 3.1 Pro | 1,048,576 | 200,000 | 81% |
| Claude Opus 5 / Sonnet 5 / Fable 5 | 1,000,000 | 200,000 | 80% |
| Grok 4.6 | 500,000 | 200,000 | 60% |
| GPT 5.6 | 372,000 | 200,000 | 46% |
| Claude Haiku 4.5 | 200,000 | 200,000 | — |

הערך נקבע בפתיחת הסשן לפי המודל שהסשן נפתח עליו, **וגם בכל החלפה באמצע שיחה**:
כל שורה בתפריט
`/model`
כבר נושאת את הסימון שפותח את החלון הגדול של אותו מודל, כך שהבחירה לא נופלת
חזרה ל‑200k. (Claude Code יודע רק 200k או 1M לשמות האלה — לכן גרוק ב‑500k ו‑GPT
ב‑921k נפתחים כ‑1M בצד של Claude Code, והתקרה האמיתית מתגלה מהספק אם עוברים אותה.)

## המתג

`claude` הרגיל הוא נקודת הכניסה היחידה. מתג קובע אם הסשן עובר דרך השרת המקומי
או ישר ל‑Anthropic. **ברירת המחדל: דלוק.**

```bash
ccx off     # claude → ישר ל‑Anthropic, מודלים של קלוד בלבד
ccx on      # claude → כל המודלים של כל הספקים
ccx mode    # מה המצב כרגע
```

אם השרת המקומי לא זמין באותו רגע — לא רץ, באמצע עדכון, נתקע — הסשן **לא נכשל**:
מודפסת אזהרה ו‑Claude Code נפתח בדרך הרגילה, ישירות מול Anthropic. זו כל
הסיבה שיש מתג ולא הדלקה קבועה.

## שימוש

```bash
claude                      # הדרך הרגילה — לפי המתג
ccx                         # סשן דרך השרת במפורש, בלי קשר למתג
ccx gpt-5.6-luna            # קובע את המודל הזה כברירת מחדל מכאן והלאה
ccx --list                  # המודלים שבתפריט כרגע
ccx --list --all            # גם המוסתרים, מסומנים
ccx --refresh               # בונה מחדש את סינון הדור הנוכחי + הסוכנים
ccx --agents                # רק הסוכנים
ccx --login                 # התחברות בדפדפן, ספק אחרי ספק
ccx --login codex           # התחברות לספק אחד
ccx --status                # המתג, מצב השרת, ולמי כבר התחברת
ccx --update                # עדכון השרת והפעלה מחדש
ccx -- --continue           # כל מה שאחרי -- עובר ל‑claude עצמו
```

בתוך הסשן `/model` מציג את המודלים המקובצים לפי ספק, בדיוק כמו בתפריט הרגיל.

## התקנה ראשונה

```bash
brew install cliproxyapi
./install.sh          # בוחרים את multi-model
ccx --login           # ומאשרים בדפדפן, ספק אחרי ספק
ccx --refresh         # בונה את רשימת המודלים
```

לאחר מכן `ccx --list` אמור להראות מודלים.

## עדכון

```bash
ccx --update
```

מושך את הגרסה החדשה של השרת ומפעיל אותו מחדש. ספקים ומודלים שנוספו בו במעלה
הזרם נכנסים לתפריט מעצמם, בלי לגעת בקוד כאן.

## בדיקה עצמית

```bash
./test-picker.sh
```

מריץ את לוגיקת הסינון על קטלוג מדומה ובודק שנשאר בדיוק הדור הנוכחי, שגרסה
ישנה לא חוזרת בהרצה הבאה, שמודל שמוגש בשני ערוצים נחסם בשניהם, שברירת המחדל של `claude` הרגיל חוזרת למקומה בסוף
הסשן גם אחרי סשן שנהרג, ושגודל הקונטקסט נלקח מהספק ולא מניחוש.

## מה נמצא איפה

```
~/.claude/scripts/ccx                    ← המפעיל
~/.claude/scripts/ccx-models.py          ← מי נכנס לתפריט ומי לא
$(brew --prefix)/etc/cliproxyapi.conf    ← הגדרות השרת (loopback בלבד)
~/.cli-proxy-api/                        ← קובצי ההתחברות של הספקים
~/.cli-proxy-api/local-key               ← מפתח מקומי אקראי, נוצר בהתקנה
~/.cli-proxy-api/ccx-defaults.json       ← המודל וה‑effort של ccx
~/.cli-proxy-api/ccx-catalogue.json      ← כל מודל שנראה אי פעם (בסיס לסינון)
~/.cli-proxy-api/ccx-mode                ← המתג (חסר = דלוק)
~/.claude/agents/ask-*.md                ← סוכן משנה לכל ספק
~/.zshrc                                 ← PATH + הפניית `claude` למתג
```

## אבטחה

השרת מאזין **רק** על 127.0.0.1 ודורש את המפתח המקומי האקראי בכל בקשה (בקשה בלי
מפתח מקבלת 401). ממשק הניהול מרוחק כבוי לגמרי. אל תפתח את הפורט הזה החוצה — כל
מי שמגיע אליו מדבר בשם המנויים שלך.

- מנוי פעיל אצל כל ספק שתרצה להתחבר אליו
