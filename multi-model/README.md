# ccx — כמה מנויי בינה מלאכותית בתוך Claude Code אחד

`ccx` מפעיל את Claude Code הרגיל שלך מול המודלים שכלולים במנויים האחרים שלך.
אותה סביבת עבודה, אותם כלים, אותם סקילים, אותם הוקים, אותן הרשאות ואותה היסטוריה —
אבל אפשר לבחור גם מודלים של ChatGPT/Codex, גוגל Antigravity, Grok וקלוד.

החיבור נעשה באמצעות התחברות בדפדפן למנוי הקיים. אין צורך במפתח API, ואין נפילה
אוטומטית לחיוב לפי שימוש. אם מנוי נגמר או הגיע למכסה שלו, הבקשה נכשלת במקום
לעבור למסלול חיוב אחר.

> **בקצרה:** מתקינים פעם אחת, מתחברים לכל ספק, ואז בוחרים מודל מתוך `/model`
> כמו בכל שיחת Claude Code רגילה.

---

## מה מקבלים

- תפריט מודלים אחד בתוך Claude Code.
- גישה למודלים ממספר ספקים באמצעות המנויים הקיימים שלך.
- אפשרות משולבת בשם `Fable Plan → Opus` — פייבל מתכנן ואופוס מבצע.
- חלון הקשר נכון לכל משפחת מודלים, במקום הנחת ברירת מחדל של 200 אלף.
- שמירת מודל ורמת מאמץ נפרדת לשיחות `ccx`.
- סוכני משנה ייעודיים ל‑ChatGPT, גוגל ו‑Grok.
- מתג שמאפשר לחזור מיד לקלוד הרגיל.
- חזרה אוטומטית לקלוד הרגיל אם הגשר המקומי אינו זמין.

## מה לא משתנה

`ccx` אינו מחליף את Claude Code ואינו בונה מעטפת עבודה חדשה. הוא מפעיל את אותה
תוכנה שכבר מותקנת אצלך. לכן ממשיכים לעבוד עם:

- קריאה ועריכת קבצים.
- הרצת פקודות.
- סקילים והוקים.
- הרשאות.
- סוכני משנה.
- המשך שיחות קיימות.
- מצב תכנון ומצב עשייה.

המודלים של הספקים האחרים פועלים בתוך סביבת Claude Code. הם אינם פותחים את
התוכנה הנפרדת של Codex, גוגל או Grok.

## איך זה עובד

המסלול של בקשה נראה כך:

```text
Claude Code
    ↓
מנקה בקשות מקומי — 127.0.0.1:8316
    ↓
CLIProxyAPI — 127.0.0.1:8317
    ↓
המנוי שאליו התחברת בדפדפן
    ↓
המודל שבחרת
```

### 1. Claude Code

זו התוכנה הרגילה. היא מציגה את המודלים, מנהלת את השיחה ומפעילה את הכלים.

### 2. מנקה הבקשות

חלק מהספקים מקבלים מבני כלים מעט שונים. התהליך המקומי מנקה חלקים לא נתמכים
מהגדרות הכלים לפני שהבקשה עוברת הלאה. תשובות זורמות חוזרות ללא שינוי.

### 3. הגשר המקומי

[CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) מחזיק את חיבורי
ההתחברות ומתרגם בין צורת הבקשה של Claude Code לצורה שהספק הנבחר מבין.

שני התהליכים מאזינים רק למחשב המקומי. הם אינם פתוחים לרשת.

## המודלים בתפריט

Claude Code מושך את הרשימה ישירות מהגשר המקומי. `ccx` מסנן אותה כדי להציג רק
את הדור הנוכחי של כל קו מודלים. גרסה חדשה נכנסת, והגרסה הישנה נעלמת מהתפריט.

דגמים מוקטנים, דגמי צד ומחוללי תמונות או וידאו מוסתרים. אפשר לראות גם אותם
באמצעות:

```bash
ccx --list --all
```

דוגמה לרשימה הנוכחית:

| ספק | מודלים |
|---|---|
| ChatGPT | GPT 5.6 Luna, Sol, Terra |
| גוגל Antigravity | Gemini Flash, Gemini Pro |
| Grok | Grok 4.6 |
| קלוד | Fable 5, Opus 5, Sonnet 5, Haiku 4.5 |

הרשימה יכולה להשתנות בלי עדכון למסמך הזה. מקור האמת הוא:

```bash
ccx --list
```

## האפשרות המשולבת: Fable Plan → Opus

בתפריט `/model` מופיעה אפשרות קבועה:

```text
Fable Plan → Opus
```

ההתנהגות שלה:

1. במצב תכנון — Claude Fable 5 בונה את התוכנית.
2. לאחר יציאה ממצב תכנון — Claude Opus 5 מבצע את העבודה.
3. שני השלבים מקבלים חלון הקשר של מיליון אסימונים.
4. המעבר מתבצע באמצעות מצב `opusplan` המובנה של Claude Code.
5. הבחירה נשמרת גם לשיחה הבאה של `ccx`.

המיפוי שמאחורי האפשרות:

```bash
ANTHROPIC_DEFAULT_OPUS_MODEL='claude-fable-5[1m]'
ANTHROPIC_DEFAULT_SONNET_MODEL='claude-opus-5[1m]'
```

Claude Code משתמש בדרך כלל במשבצת אופוס לתכנון ובמשבצת סונט לעשייה. `ccx`
ממפה את המשבצת הראשונה לפייבל ואת השנייה לאופוס. שורות המודלים הרגילות
בתפריט משתמשות בשמות מלאים, ולכן הן אינן משתנות.

### איך משתמשים

1. מפעילים `ccx`.
2. מקלידים `/model`.
3. בוחרים `Fable Plan → Opus`.
4. עוברים למצב תכנון באמצעות `Shift+Tab`.
5. מאשרים את התוכנית ועוברים למצב עשייה.

אפשר לבחור אפשרות אחרת בכל רגע דרך `/model`.

## גדלי חלונות ההקשר

Claude Code מכיר מראש בעיקר את הגדלים של מודלי קלוד. לשמות אחרים הוא עלול
להניח חלון של 200 אלף בלבד ולכווץ שיחה מוקדם מדי. `ccx` קורא את הגודל שהספק
מדווח ומשייך אותו למודל.

| משפחה | חלון שמוגדר ב‑ccx |
|---|---:|
| Gemini Flash / Pro | 1,048,576 |
| Claude Fable / Opus / Sonnet | 1,000,000 |
| GPT 5.6 | 921,000 |
| Grok 4.6 | 500,000 |
| Claude Haiku 4.5 | 200,000 |

Claude Code יודע לפתוח לשמות האלה חלון של 200 אלף או מיליון. לכן מודל שמדווח
למשל על 500 אלף עשוי להופיע בצד של Claude Code עם סימון מיליון, בעוד הספק עצמו
עדיין אוכף את התקרה האמיתית שלו.

כל שורה בבורר כבר מכילה את הסימון הנדרש. החלפה באמצע שיחה אינה מחזירה את
החלון ל‑200 אלף.

## ברירת המחדל ורמת המאמץ

המודל ורמת המאמץ שבחרת בתוך `ccx` נשמרים לשיחת `ccx` הבאה.

ל‑Claude Code הרגיל יש ברירת מחדל משלו. `ccx` שומר את הבחירה הרגילה בצד,
מכניס את הבחירה הרב‑מודלית בזמן השיחה, ומחזיר את הבחירה המקורית בסיום.

כך מודל מהגשר המקומי אינו נשאר בטעות בהגדרות של קלוד הרגיל.

אם שיחה נהרגת בכוח ולא מספיקה להחזיר את ההגדרות, השיחה הבאה מזהה שהבעלים
הקודם כבר לא פעיל ומשחזרת את ההגדרות.

בדיקה:

```bash
ccx --status
```

## שתי דרכי הפעלה

### הפעלה מפורשת

```bash
ccx
```

תמיד פותח שיחה דרך הגשר המקומי.

### הפעלה דרך הפקודה הרגילה

בזמן ההתקנה אפשר להפנות את הפקודה הרגילה אל `ccx`. מתג קובע לאן היא תפנה:

```bash
ccx on
ccx off
ccx mode
```

- `on` — הפקודה הרגילה מציגה מודלים מכל הספקים.
- `off` — הפקודה הרגילה פונה ישירות לקלוד, ללא הגשר המקומי.
- `mode` — מציג את המצב הנוכחי.

אם המתג דלוק אבל הגשר אינו זמין, הפקודה הרגילה פותחת Claude Code ישירות מול
קלוד במקום להיכשל. הפעלה מפורשת באמצעות `ccx` כן מחזירה שגיאה, כי ביקשת
במפורש להשתמש בגשר.

## התקנה ראשונה

### דרישות

- macOS.
- Homebrew.
- Claude Code מותקן.
- Node.js.
- Python 3.
- מנוי פעיל אצל כל ספק שרוצים לחבר.

### התקנה

```bash
git clone https://github.com/yedidya-buildfy/claude-addons.git
cd claude-addons
./install.sh
```

במתקין בוחרים את `multi-model`.

המתקין:

1. מתקין את CLIProxyAPI באמצעות Homebrew, אם הוא חסר.
2. יוצר מפתח מקומי אקראי.
3. כותב הגדרה שמאזינה רק ל‑127.0.0.1.
4. מעתיק את סקריפטי `ccx`.
5. מפעיל את השירות המקומי.
6. מציע להפנות את הפקודה הרגילה למתג הרב‑מודלי.

לאחר ההתקנה טוענים מחדש את הגדרות המעטפת:

```bash
source ~/.zshrc
```

## התחברות לספקים

להתחברות מודרכת לכל הספקים:

```bash
ccx --login
```

להתחברות לספק אחד:

```bash
ccx --login claude
ccx --login codex

ccx --login xai
ccx --login kimi
```

לאחר ההתחברות:

```bash
ccx --refresh
ccx --list
```

### החלפת חשבון אצל ספק

```bash
ccx --logout codex
ccx --login codex
```

היציאה אינה מוחקת מיד את קובץ ההתחברות הישן. היא משנה את שמו עם חותמת זמן,
כדי שיהיה אפשר לחזור אחורה אם ההתחברות החדשה נכשלת.

## סוכני משנה של ספקים אחרים

`ccx` יוצר סוכן משנה אחד לכל ספק שאינו קלוד:

```text
ask-chatgpt
ask-antigravity
ask-grok
```

כך אפשר להשאיר את הלולאה הראשית על קלוד ולמסור משימה נפרדת למודל אחר.
הסוכן מקבל אותם כלי קריאה, עריכה והרצת פקודות.

יצירה מחדש:

```bash
ccx --agents
```

הסוכנים נכתבים מחדש גם בזמן `ccx --refresh`, ולכן עריכה ידנית שלהם תידרס.
כאשר יוצא דור חדש, הם עוברים אוטומטית למודל הנוכחי המתאים.
